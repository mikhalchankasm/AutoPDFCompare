# ТЗ: Визуальная страница сравнения — Вариант B (Матрица/таблица + heatmap)

## 1. Цель
Реализовать страницу **сводного визуального сравнения** двух документов (PDF ревизии A и B) в виде **таблицы-матрицы** со статусами, метриками изменений и **heatmap-подсветкой** величины изменений.  
Страница должна быстро отвечать на вопросы:
- какие листы **добавлены/удалены**
- какие листы **изменены**, и насколько сильно
- как устроено **сопоставление A-B** при вставках/перестановках
- куда кликнуть, чтобы открыть **OLD/NEW/DIFF** просмотр

---

## 2. Термины
- **A** — исходная ревизия документа
- **B** — новая ревизия документа
- **Seq(B)** — порядковая позиция листа в документе B (1..N)
- **Match** — найденное соответствие страницы A для страницы B
- **Status**:
  - `MATCH` — страница B имеет соответствие в A
  - `ADDED` — страница есть только в B
  - `REMOVED` — страница есть только в A (в таблице может отображаться отдельным блоком)
  - `MOVED` — (опционально) соответствие найдено, но порядок изменён
- **Change level**:
  - `UNCHANGED`, `MINOR`, `MODERATE`, `MAJOR` (пороговые уровни настраиваются)
- **Diff %** — числовая метрика различия (0..100), используемая для heatmap
- **? boxes** — количество областей изменений (bboxes), если доступно

---

## 3. Входные данные (source of truth)
### 3.1 JSON-структура результата сравнения
Страница строится из `report.json` / `summary.json`.

Минимально необходимые поля для каждой строки:
- `b_index` (Seq(B))
- `a_index | null`
- `status` (`MATCH/ADDED/REMOVED/MOVED`)
- `change_level` (`UNCHANGED/MINOR/MODERATE/MAJOR` или null)
- `diff_percent | null`
- `bboxes_count | null`
- `assets`:
  - `thumb_old` (если есть A)
  - `thumb_new` (если есть B)
  - `thumb_diff` (если MATCH)
  - `overlay`/`mask`/`hires` (ссылки на детальные ресурсы)
- `pair_dir` или аналогичный идентификатор для построения ссылок

### 3.2 Нормализация данных
- `diff_percent` хранить числом (float), выводить с округлением до 3 знаков
- для `ADDED/REMOVED` метрики `diff_percent`, `bboxes_count` = `null` (показывать “—”)

---

## 4. Страница “Change Matrix” — структура UI

## 4.1 Header (шапка)
Элементы:
1) Заголовок: `Revision Compare — Change Matrix`
2) Подзаголовок:
   - `Doc A: <name/rev> (<pages>)  >  Doc B: <name/rev> (<pages>)`
3) Быстрые метрики (мини-карточки):
   - `Changed`, `Added`, `Removed`, `Unchanged` (и `Moved` если используется)
4) Поле поиска:
   - placeholder: `Search sheet…`
   - ищет по: `A page`, `B page`, `sheet id/name` (если есть), `Seq(B)`

## 4.2 Filter chips (быстрые фильтры)
Фильтры должны комбинироваться:
- По статусу: `All`, `Changed`, `Added`, `Removed`, `Moved`, `Unchanged`
- По уровню: `Major`, `Moderate`, `Minor`
- По наличию сопоставления: `Matched only`, `Unmatched only` (опционально)
- По диапазону `Diff %` (slider или preset: `<0.5%`, `0.5–2%`, `>2%`) — опционально

## 4.3 Основной блок: Таблица-матрица
Таблица в карточке с фиксированной шапкой (sticky header) и скроллом по вертикали.

### 4.3.1 Колонки (MVP)
1) `Seq (B)` — число
2) `A page` — `A{n}` или `—`
3) `B page` — `B{n}`
4) `Status` — pill badge
5) `Change level` — pill badge (если применимо)
6) `Diff %` — число, **heatmap background**
7) `? boxes` — число или “—”
8) `Preview` — мини-эскиз (tiny thumbnail)
9) `Open` — иконка/кнопка (переход в детальный просмотр)

### 4.3.2 Опциональные колонки (после MVP)
- `Match confidence` (`EXACT/PROBABLE/NONE`)
- `Moved from > to` (если `MOVED`)
- `Page size` (A3/A1, ориентация)

### 4.3.3 Сортировка
Поддержать сортировку по:
- `Seq(B)` (default)
- `Diff %` (desc/asc)
- `Change level` (major>minor)
- `Status` (группировка)

### 4.3.4 Группировка строк (опционально)
- Group by: `Status`
  - сначала `MATCH`, затем `ADDED`, затем `REMOVED` (если отображаются в одной таблице)

---

## 5. Цветовая система (легенда)
## 5.1 Status badge colors
- `MATCH`: нейтральный (серый/синий)
- `ADDED`: фиолетовый
- `REMOVED`: красный
- `MOVED`: синий/индиго

## 5.2 Change level badge colors
- `UNCHANGED`: зелёный
- `MINOR`: светло-жёлтый
- `MODERATE`: оранжевый
- `MAJOR`: красный/розовый

## 5.3 Heatmap для колонки Diff %
Требования:
- фон ячейки `Diff %` должен иметь **градиент интенсивности** по величине `diff_percent`
- низкие значения (около 0) — почти белый
- средние — лёгкий оранжевый
- высокие — лёгкий красный
- режим масштабирования:
  - MVP: фиксированные пороги (настройка)
  - Post-MVP: авто-нормализация (min/max по документу) + fallback на фикс пороги

Обязательное:
- текст `Diff %` всегда читаем (контраст, возможно авто-цвет текста)

## 5.4 Legend (блок легенды)
Справа или под таблицей:
- цветовые чипы + подписи:
  - Major / Moderate / Minor / Unchanged
  - Added / Removed / Missing

---

## 6. Превью и переход в детали
## 6.1 Preview (в таблице)
В ячейке Preview:
- MVP: маленький прямоугольник с миниатюрой `thumb_diff` (если MATCH) или `thumb_new` (если ADDED)
- если ресурсов нет — placeholder `OLD | NEW | DIFF` или “Preview”

## 6.2 Поведение клика
Клик по строке или по кнопке `Open`:
- открывает **детальный просмотр** конкретного листа:
  - вариант 1: отдельная страница `/pages/<id>.html`
  - вариант 2: модальное окно (modal) поверх таблицы
  - вариант 3: правый “details drawer” (панель)

Минимум в деталях:
- `OLD / NEW / DIFF` табы
- кнопки: открыть high-res (если есть)

---

## 7. Мобильная версия
Требования:
- таблица должна быть читаемой:
  - либо горизонтальный скролл таблицы
  - либо “responsive rows” (каждая строка превращается в карточку)
- рекомендуемый подход:
  - Desktop: таблица
  - Mobile: карточки (одна карточка = один лист)

Карточка (mobile row) должна содержать:
- Seq(B), A page, B page
- Status + Change level
- Diff % (с мини heat bar)
- Preview
- кнопка Open

---

## 8. Производительность
- до 200+ строк без лагов
- использовать:
  - виртуализацию списка (post-MVP)
  - ленивую загрузку превью (lazy-load images)
- сортировка/фильтр должны работать за <200ms (локально на фронте при разумном объёме)

---

## 9. Доступность и UX
- подсказки (tooltips) на:
  - Diff %, ? boxes, статус, confidence
- понятные пустые состояния:
  - “No pages match filter”
- состояние загрузки:
  - skeleton rows для таблицы
- экспорт/скачивание:
  - кнопка `Download report.zip` (если есть)
  - опционально: `Export CSV` текущего фильтра

---

## 10. Конфигурируемые параметры
- пороги change_level по `diff_percent`:
  - `UNCHANGED` ? t0
  - `MINOR` ? t1
  - `MODERATE` ? t2
  - `MAJOR` > t2
- режим heatmap:
  - fixed thresholds / auto normalize
- включение/выключение:
  - `MOVED` логики и отображения
  - блока `REMOVED` (в конце/отдельной вкладкой)

---

## 11. Критерии приёмки
1) Таблица отображает все страницы B (Seq(B)=1..N) и корректно показывает `A page` или “—”
2) `ADDED` страницы подсвечены и не имеют Diff%/? boxes (показывают “—”)
3) `Diff %` имеет heatmap подсветку, пропорциональную значению
4) Фильтры работают корректно (Changed/Added/Removed + уровни)
5) Поиск находит строки по A/B/Seq
6) Клик по строке/кнопке `Open` открывает детальный просмотр и показывает OLD/NEW/DIFF
7) На мобиле интерфейс остаётся удобным (таблица не ломается; либо карточки)

---

## 12. MVP-реализация (минимум)
- Header + Summary counters
- Search
- Filter chips: All / Changed / Added / Removed + Major/Moderate/Minor
- Таблица с колонками (MVP)
- Heatmap подсветка Diff %
- Open > переход на детальную страницу/модалку

---

## 13. Post-MVP улучшения
- виртуализация строк
- match confidence колонка
- группировка по статусам
- inline mini-sparkline/бар в Diff%
- экспорт CSV текущего вида
- deep-zoom viewer для high-res
