# ТЗ: Сервис сравнения двух документов (чаще PDF) и генерация отчёта

## 0. Цель
Сделать сервис, который принимает **2 документа** (обычно PDF: ревизия A и ревизия B), выполняет **сопоставление страниц**, находит **добавленные/удалённые/изменённые/без изменений** листы, генерирует **дифф в виде изображений**, и собирает **удобный отчёт для просмотра на десктопе и мобильных устройствах**.

Ключевой продуктовый результат:
- **Интерактивный отчёт (HTML, responsive)** как основной формат просмотра.
- **Экспорт PDF (опционально)** как “официальная копия” для пересылки/архивации.

---

## 1. Область применения и сценарии
### 1.1 Основные сценарии
1) Пользователь загружает `Document A` и `Document B`.
2) Система строит соответствия страниц A - B (учитывая вставки/удаления/перестановки).
3) Система классифицирует страницы:
   - `UNCHANGED` — без изменений
   - `CHANGED` — изменено содержимое
   - `ADDED` — новая страница в B
   - `REMOVED` — страница есть в A, но отсутствует в B
   - `MOVED` — опционально (если страница та же, но поменяла порядок)
4) Система генерирует изображения для отчёта:
   - превью `OLD`, `NEW`, `DIFF`
   - по запросу — high-res версии
5) Система формирует отчёт:
   - страница “Сводка” (dashboard + визуальная карта листов)
   - детальная часть по листам с навигацией
6) Пользователь смотрит отчёт:
   - удобно на десктопе (панель навигации, фильтры)
   - удобно на мобиле (карточки, вкладки OLD/NEW/DIFF, pinch-zoom)

---

## 2. Входные данные
### 2.1 Поддерживаемые форматы
- MVP: `PDF`
- Расширение: изображения/сканы (`TIFF`, `PNG`, `JPG`), возможно `DWG` (не входит в MVP)

### 2.2 Ограничения MVP
- Кол-во страниц: до N (задаётся конфигурацией)
- Размер файла: до M MB (задаётся конфигурацией)
- Допускаются сканированные PDF без текста (работа через визуальные отпечатки)

---

## 3. Выходные данные (артефакты)
### 3.1 Основной отчёт
- **HTML (responsive)** + ассеты, упакованные в ZIP:
  - `index.html` — сводка + карта листов
  - `pages/` — детальные страницы или якорные секции (вариант реализации)
  - `assets/thumbs/` — превью изображений
  - `assets/hires/` — high-res изображения или tiles
  - `report.json` — машинное описание результатов сравнения (source of truth)

### 3.2 Экспорт (опционально)
- `report.pdf` — печатная/официальная версия
- (позже) `report.pptx` — презентационный формат

---

## 4. Термины и статусы
### 4.1 Статусы страницы
- `UNCHANGED` — визуально/семантически без изменений (по порогу)
- `CHANGED` — есть изменения (по порогу)
- `ADDED` — страница есть только в B
- `REMOVED` — страница есть только в A
- `MOVED` — (опционально) найдено соответствие, но индекс/порядок другой

### 4.2 Типы соответствия (match confidence)
- `EXACT` — высокий confidence (например, совпал fingerprint/номер листа)
- `PROBABLE` — средний confidence (визуально близко)
- `NONE` — соответствие не найдено

---

## 5. Алгоритм обработки (pipeline)
## 5.1 Извлечение страниц
Для каждого документа (A и B):
- Получить список страниц и метаданные:
  - размер (width/height), ориентация
  - номер страницы (индекс)
- Извлечь текст (если доступен):
  - raw text
  - нормализованный text (lowercase, убрать лишние пробелы и т.п.)
- Сгенерировать изображения:
  - `thumb` (например 150–300 DPI или фикс ширина)
  - `base` (для диффа, средний DPI)

## 5.2 Отпечатки (fingerprints)
Для каждой страницы:
- `text_fingerprint` — hash нормализованного текста (если текст есть)
- `visual_fingerprint` — perceptual hash (pHash/dHash/aHash) от thumb
- `layout_features` — размер страницы, ориентация, опционально рамка/штамп-область

## 5.3 Сопоставление страниц A - B (page matching)
Цель: устойчиво переживать вставки/удаления/перестановки.
Скоринг соответствия (пример):
- вес 1: совпадение “идентификатора листа” (если извлечён из штампа/оглавления) — высокий вес
- вес 2: близость visual_fingerprint — средний вес
- вес 3: близость по тексту — средний вес
- вес 4: совпадение размера/ориентации — вспомогательный вес

Результат:
- для каждой страницы B:
  - найденная страница A или `NONE`
  - confidence: EXACT/PROBABLE/NONE
- затем построить:
  - `ADDED` (B без match)
  - `REMOVED` (A, которые не сматчились ни с одной B)
  - `MOVED` (если match есть, но индекс сильно отличается) — опционально

## 5.4 Определение “изменено/без изменений”
Для пар A-B:
- выполнить сравнение изображений (на base DPI):
  - получить метрику различий (например SSIM / diff ratio / pixel delta)
- если метрика < порога > `UNCHANGED`, иначе `CHANGED`

Порог должен быть настраиваемым.

## 5.5 Генерация DIFF
Для пар A-B:
- `DIFF overlay` (MVP):
  - OLD и NEW совмещаются (align)
  - формируется изображение наложения (например pseudo-color)
- опционально:
  - `highlight mask` (пятна изменений)
  - `blink` режим (переключение old/new) — реализуется на фронте

## 5.6 High-Res просмотр (пост-MVP или опционально)
Два режима:
1) MVP: high-res PNG/JPG на страницу (ограниченный DPI)
2) Best UX: deep-zoom tiles (256/512px) для OLD/NEW/DIFF

---

## 6. Структура отчёта (UX требования)
## 6.1 Страница “Сводка” (Dashboard)
Содержит:
1) Метаданные:
   - имя файла, дата, ревизия (если известна), размер, число страниц
   - параметры сравнения (DPI, пороги, режим align)
2) Счётчики:
   - Unchanged / Changed / Added / Removed / Moved
3) Визуальная “карта листов”:
   - сетка карточек-миниатюр (как “маленькие страницы”)
   - каждая карточка содержит:
     - номер/идентификатор листа
     - статус badge (цвет/иконка)
   - клик/тап по карточке > переход на детальную секцию/страницу
4) Фильтры:
   - показать только Changed
   - Added / Removed
   - поиск по номеру/названию листа (если есть)

## 6.2 Детализация по листам
Для каждого листа (в порядке документа B по умолчанию):
- Заголовок:
  - идентификатор листа B
  - ссылка/упоминание соответствующего A (если есть)
  - статус + confidence
  - (опционально) указание перемещения: A# > B#
- Блок просмотра превью:
  - Desktop: `OLD | NEW | DIFF` (3 колонки)
  - Mobile: одна зона просмотра + вкладки `OLD/NEW/DIFF`
- Кнопки:
  - открыть OLD hi-res
  - открыть NEW hi-res
  - открыть DIFF hi-res
  - (опционально) blink
- Навигация:
  - предыдущий/следующий
  - “вернуться к сводке”
  - (desktop) sticky sidebar со списком листов и фильтрами

## 6.3 Мобильные требования
- адаптивная вёрстка
- просмотр изображений:
  - pinch-zoom
  - double-tap zoom
- быстрые переходы:
  - свайп или кнопки prev/next
- ленивые загрузки:
  - сначала thumbs
  - high-res только по запросу

---

## 7. Формат `report.json` (машинное представление результата)
`report.json` — единственный источник правды, из него генерируются HTML/PDF/др.

Минимальные поля (пример логической структуры):
- `documents`:
  - `a`: {name, size_bytes, page_count, hash, created_at?}
  - `b`: {name, size_bytes, page_count, hash, created_at?}
- `settings`:
  - dpi_thumb, dpi_diff, thresholds, align_mode
- `summary`:
  - counts: {unchanged, changed, added, removed, moved}
- `pages`[] — список страниц (обычно в порядке B):
  - `b_index`
  - `a_index` | null
  - `status` (UNCHANGED/CHANGED/ADDED/REMOVED/MOVED)
  - `match_confidence` (EXACT/PROBABLE/NONE)
  - `diff_metric` (число/структура)
  - `assets`:
    - `thumb_old`, `thumb_new`, `thumb_diff`
    - `hires_old`, `hires_new`, `hires_diff` (или tiles manifest)
  - `notes` (опционально: причины, подсказки)

## 8. Упаковка артефактов
Выдача пользователю:
- `report.zip`
  - `index.html`
  - `report.json`
  - `assets/thumbs/...`
  - `assets/hires/...` (если есть)
  - `pages/...` (если разнесено по файлам)

Требования:
- открывается локально без сервера
- корректно работает в мобильном браузере
- ссылки относительные

---

## 9. Нефункциональные требования
### 9.1 Производительность
- thumbs генерируются быстро (параллельно)
- diff создаётся в фоне/очереди (если много страниц)
- отчёт должен быть читаемым даже при 100+ страницах:
  - виртуализация/ленивая загрузка
  - фильтрация без лагов

### 9.2 Качество и устойчивость
- устойчивость к сканам (нет текста)
- корректная обработка разных форматов (A4/A3/A1, портрет/альбом)
- настраиваемые пороги “без изменений”
- логирование процесса и диагностика ошибок

### 9.3 Безопасность
- хранение файлов изолированно по пользователю/задаче
- автоочистка временных данных по TTL
- (если SaaS) ограничения по доступу, временные ссылки на скачивание

---

## 10. MVP-объём (минимально жизнеспособно)
1) PDF A+B загрузка
2) Извлечение страниц, thumbs
3) Fingerprints + сопоставление страниц (без OCR штампа на старте)
4) Классификация: added/removed/changed/unchanged
5) Генерация DIFF overlay (preview)
6) Генерация `report.json`
7) Генерация HTML отчёта:
   - Dashboard + карта листов (кликабельная)
   - Детализация с превью и навигацией
   - Фильтр “только изменённые”
   - Mobile layout с вкладками OLD/NEW/DIFF
8) ZIP-выдача отчёта

---

## 11. Post-MVP улучшения
- deep-zoom tiles для high-res (лучший UX для A1/A0)
- OCR/извлечение номера листа из штампа > точнее matching
- highlight-mask и/или blink режим
- экспорт PDF/PPTX из `report.json`
- совместное комментирование (аннотации) и история сравнений

---

## 12. Критерии приёмки
Отчёт считается корректным, если:
1) На “Сводке” корректные счётчики по статусам
2) Карта листов кликабельна и ведёт на правильные листы
3) Для каждого листа отображаются корректные превью:
   - OLD/NEW/DIFF (в соответствии со статусом)
4) На мобиле:
   - нет горизонтального “развала” верстки
   - удобно переключать OLD/NEW/DIFF
   - изображения можно увеличивать
5) Удалённые/добавленные листы корректно помечаются
6) Отчёт открывается локально из ZIP (без внешнего сервера)
