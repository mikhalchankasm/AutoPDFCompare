# Независимая перепроверка PDFCompare Local — 2026-07-14

Проверенная ревизия: `90ba10fb1e9af8ce7eee5b060c7b216e035df233` (`master`, tag `v0.1.19`, `origin/master` совпадал с HEAD). Исходный отчёт: `docs/reviews/2026-07-13_review.md`, ревизия `db8c1d95f4150749dfa19e36389d7e9b80ca7a08`.

## 1. Резюме

Исправления v0.1.17–v0.1.19 в целом состоятельны. Из девяти исходных находок семь закрыты, одна закрыта частично, одна остаётся открытой:

- **closed:** PDF-002, PDF-003, PDF-004, PDF-005, PDF-006, PDF-007, PDF-009;
- **partially closed:** PDF-001 — однородный legacy-percent набор сохраняется, смешанный percent+mm набор всё ещё молча экспортируется целиком в mm;
- **open:** PDF-008 — полная навигация по-прежнему дублируется в каждой HTML-странице, то есть O(N²) не изменилось.

Критических дефектов не найдено. Добавлены три новые `minor`-находки: заявленный strict-mypy gate фактически не strict и исключает операционные scripts; CLI/MCP не используют новую локализацию ошибок; force-kill MCP имеет узкую гонку переиспользования PID.

Текущий код прошёл 170 тестов и coverage gate 88,16% как в проектном окружении, так и в чистом Python 3.12.10 из hash-lock. Оба PyInstaller-варианта собраны и запускаются. Runtime-lock и full-lock устанавливаются с `--require-hashes`, `pip check` чист, `pip-audit` не нашёл известных уязвимостей. Inno Setup в системе отсутствует, поэтому реальная установка/тихое обновление/удаление не проверены.

### PDF-001 — что именно осталось

Исправлен главный частый сценарий: открыть однородный старый percent-набор и нажать OK. Однако picker по-прежнему имеет одну `unit_var` на весь диалог. Для набора из percent- и mm-региона `incoming_unit()` выбирает mm, после чего `_accept()` сериализует **каждый** регион в mm. Комментарий называет mm «единственным сохраняющимся представлением», но это не так: исходную unit можно хранить на каждом внутреннем регионе либо запросить явное подтверждение конвертации.

Рекомендация: сохранить unit per region и менять её только при явном пользовательском действии; как минимум показать предупреждение о миграции mixed-набора. Добавить настоящий picker-level тест, а не только тест чистых conversion helpers.

### PDF-003 — остаточный эксплуатационный риск

Кооперативный путь работает. В smoke на пяти A4-листах с rerender 600 DPI отмена завершилась примерно через 18 секунд от запуска worker — близко к default `grace_sec=20`. На более тяжёлом листе один render/checkpoint может превысить grace, после чего MCP намеренно применит force-kill и снова потеряет транзакционный unwind. Это не переоткрывает PDF-003: timeout fallback заявлен явно и возвращает `forced=true`, но безопаснее ждать подтверждение worker-а о входе в rollback либо иметь более консервативный/адаптивный timeout для rerender.

## 3. Новые находки

### RECHECK-001 — type gate не strict и не проверяет MCP scripts

**Серьёзность:** minor

**Файлы:** `scripts/lint.ps1:23-26`, `pyproject.toml:28-34`, `scripts/pdfcompare_mcp.py:1120-1134`, `AGENTS.md`

`AGENTS.md` называет mypy strict и жёстким gate. Фактически конфигурация не включает `strict = true`, а `scripts/lint.ps1` запускает mypy только для `compare_pdfs.py`, `pdfcompare_gui.py`, `pdfcompare_core` и `pdfcompare_ui`. Папка `scripts/` получает лишь py_compile и ruff.

Дополнительный запуск тем же mypy 2.2.0 из текущего hash-lock с включением `scripts/pdfcompare_mcp.py` нашёл реальную ошибку:

```text
scripts/pdfcompare_mcp.py:1134: error: Argument "transport" to "run" of "FastMCP"
has incompatible type "str"; expected "Literal['stdio', 'sse', 'streamable-http']"  [arg-type]
```

Официальный CI будет зелёным при этой ошибке. Рекомендация: включить как минимум `scripts/pdfcompare_mcp.py` и `scripts/pdfcompare_worker.py` в mypy gate, валидировать transport до вызова и сузить его тип до Literal. Либо действительно включить strict поэтапно, либо убрать слово strict из документации.

### RECHECK-002 — двуязычные engine errors не доходят до CLI и MCP

**Серьёзность:** minor

**Файлы:** `pdfcompare_core/cli.py:70-77`, `scripts/pdfcompare_mcp.py:603-640`, `:644-788`, `:792-943`, `scripts/pdfcompare_worker.py:250-264`

GUI корректно вызывает `localize_error(exc, report_lang)` и выполняет обещание v0.1.19. CLI и MCP продолжают использовать `str(exc)`, который намеренно всегда русский. Фактические проверки:

- `compare_pdfs.py --lang en --dpi 5` вернул русское `DPI должен быть в диапазоне...`;
- `start_pdf_comparison(..., dpi=5, lang="en")` вернул ту же русскую ошибку;
- worker записывает `str(exc)` в status/event независимо от `request["lang"]`.

Это не ломает RU GUI, но расходится с docstring `errors.py`, где CLI/MCP прямо названы потребителями локализации, и оставляет английские agent/CLI workflows частично русскими. Рекомендация: локализовать `PDFCompareError` на CLI/MCP boundary, не меняя русский `str(exc)` в логах/traceback.

### RECHECK-003 — force-kill повторно не проверяет принадлежность PID worker-у

**Серьёзность:** minor

**Файл:** `scripts/pdfcompare_mcp.py:1062-1091`

Перед созданием marker-а код вызывает `process_matches_worker_job(pid, job_id)`, но затем до 20 секунд проверяет только `pid_exists(pid)`. Если worker завершится между poll-итерациями, а Windows быстро переиспользует тот же PID, цикл продолжит ждать и в deadline выполнит `taskkill /T /F` уже для другого процесса.

Окно узкое, но последствие разрушительное для чужого локального процесса. Рекомендация: на каждой итерации либо хотя бы непосредственно перед kill повторно проверять command line/job id; надёжнее — держать process handle/creation time или управлять worker через Windows Job Object.

## 4. Новые изменения v0.1.18–v0.1.19

### One-dir installer payload

Статически решение корректно: `PDFCompareLocal-dir.spec` использует `exclude_binaries=True` + `COLLECT`, UPX выключен; `installer.iss` рекурсивно ставит `dist/PDFCompareLocal/*`; CI строит one-file и one-dir в разных workpath и проверяет EXE/runtime DLL.

На чистом Python 3.12 обе сборки прошли. One-file размером 87 877 189 байт и one-dir EXE успешно стартовали и оставались живы после четырёх секунд. В one-dir найден `_internal/python3.dll`. PyInstaller warnings состояли из обычных conditional/optional imports; обязательного tkinterdnd2/runtime-модуля среди пропусков не было.

Реальный installer не собран: `ISCC.exe` отсутствует. Поэтому не проверены upgrade поверх старой one-file установки, закрытие запущенного приложения, `/SILENT` relaunch и uninstall cleanup.

### RU/EN errors, tooltips и help

- Каталог engine errors имеет одинаковые ключи/placeholder-ы в RU и EN; целевые тесты проходят.
- GUI локализует ошибки перед передачей из worker thread в UI queue; Tk из фоновых потоков не вызывается.
- Tooltip callbacks создаются в GUI thread и исполняются через Tk `after`; прямого нарушения thread affinity не найдено.
- GUI I18N фактически имеет 227/227 одинаковых ключей RU/EN.
- Golden layout фиксирует новую кнопку `?`, но не проверяет содержимое/позиционирование tooltip и F1 callback. Это покрытие ограниченное, а не найденный дефект.

### Dependency audit

Оба CI job по-прежнему ставят full lock с `--require-hashes`. Audit step выполняется после установки lock в test job, пишет результат в job summary и имеет `continue-on-error: true`, то есть является честным advisory gate. На 2026-07-14 фактический `pip-audit 2.10.1` в чистом full-lock окружении вернул `No known vulnerabilities found`.
