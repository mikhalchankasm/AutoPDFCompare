# PDFCompare Local v0.1.24

Глобальная история сравнений в MCP, чек-лист перед запуском и заметки к зонам в слайдере.

## Глобальная история сравнений, доступная из MCP

У MCP не было ни вкладки «История», как в GUI, ни собственного журнала: `list_pdf_comparisons` лишь сканировал одну папку на диске. Теперь есть настоящий журнал, и он **глобальный**.

- Оба журнала — GUI (`state.json`) и MCP (`mcp_history.json`) — лежат в `~/.pdfcompare_local/` (домашняя папка пользователя, **не** папка-клон MCP), поэтому переживают переустановку/переклонирование сервера. Раньше MCP-стейт жил внутри репозитория и на свежем клоне пропал бы.
- `list_comparison_history` сливает оба журнала в единый нумерованный список (новые сверху): у каждой строки порядковый `#`, стабильный `id` (`mcp:<job>` / `ui:<hash>`), метка источника (`ui` = вкладка «История» GUI, `mcp` = запуск через сервер), дата, результат, имена файлов, папка и `run_dir`.
- `restore_comparison` перезапускает прошлый прогон **в два шага**: сначала (по умолчанию) показывает параметры записи, наличие исходных PDF на диске и непересекающееся имя новой папки — ничего не запуская; по `confirm=true` стартует свежее сравнение в новую папку, не трогая оригинал.
- Worker дописывает в MCP-историю каждый завершённый прогон (готово / отменён / ошибка). Чтение обоих журналов и приведение параметров к форме для повторного запуска вынесено в `pdfcompare_core/history_index.py`, чтобы GUI и MCP не расходились.

## `preview_pdf_comparison` — чек-лист перед запуском

Агент теперь может показать сводку **до** старта и спросить подтверждение. Инструмент валидирует ровно то же, что и `start_pdf_comparison` (пути, имя папки, DPI, строгость, зоны, коллизию папки результата), но ничего не запускает — возвращает готовый к показу чек-лист:

- какой старый и какой новый файл, сколько в каждом листов и дельта листов;
- точность: DPI, `stroke_tol`, строгость — с пометкой, где значение всё ещё по умолчанию;
- исключаемые зоны: сколько и каждая одной строкой (или «нет»);
- папку и имя, куда пойдёт отчёт.

Валидация вынесена в общий хелпер, так что preview никогда не одобрит запуск, который `start` затем отклонит. Порядок в рабочем цикле агента: `prepare` → **`preview`** → показать чек-лист и получить «да/что изменить» → `start`.

## Заметки к зонам в слайдере (первый шаг)

Иногда «изменение» — не изменение: инженер просто сдвинул фрагмент, и при накладке зона краснеет, хотя по сути правки нет. Теперь это можно пометить прямо в отчёте.

- Режим «Заметка»: тянешь полупрозрачный прямоугольник в текущем масштабе и вписываешь комментарий. Три цвета: 🟢 нет изменений, 🟡 спорное, 🔴 изменение.
- Заметку можно **двигать** за тело и **менять размер** за угловые ручки, **скрывать/показывать** и удалять. Подпись сама встаёт на свободную сторону — снизу, если бокс у верхнего края листа (иначе текст вылезал за лист), сверху в остальных случаях.
- Хранятся в браузере (`localStorage`) по ключу «прогон + лист», переживают перезагрузку страницы.

Это **первый шаг**: заметки браузерные и пока **не переживают перегенерацию отчёта** и не переносятся между машинами — file://-страница не может писать на диск сама. Следующий шаг — писать заметки в файл прогона и подхватывать их при сборке отчёта.

## Слайдер: доработки по следам работы

- **Подсветка зон работает в текущем масштабе.** Раньше «Зоны» сначала вписывали лист целиком; теперь рамки рисуются там, где ты смотришь: зумнулся в область → снова нажал «Зоны» → изменения обвелись на месте. Клавиша `H` (и `Ctrl+H`) — синоним `Z`; обе теперь переключатель.
- **Мелкий шаг зума.** Рядом с «Масштаб NN%» — кнопки `−`/`+` с шагом 2% от текущего: тоньше колёсика, когда оно настроено на крупный шаг.
- **Листание строго по соседнему листу.** `←`/`→` и кнопки листов идут к непосредственному соседу, включая добавленные/удалённые (для них открывается обычный вид листа), и больше не скроллят увеличенный лист вместо перехода.

## Как получить новые MCP-инструменты

Сервер запускается напрямую из рабочего дерева, git-pull здесь нет, так что код уже актуален — но новые инструменты регистрируются только при **перезапуске самого MCP-сервера**: полностью закрой и открой Claude Desktop (новый чат недостаточно). Правки вьюера видны в новых или перегенерированных отчётах; уже собранные отчёты остаются со старым вьюером.

## Ограничение

Заметки к зонам пока браузерные (localStorage) — не переживают перегенерацию отчёта и не переносятся между машинами. Персистентное хранилище (файл прогона + чтение при сборке отчёта) — следующий шаг.
