# PDFCompare Local v0.1.16

Cancellation that actually cancels, a cancellable re-render, and reproducible builds.

## Added

- **"Отмена" for re-render** — while a re-render runs, its button becomes a cancel button, like the compare button. Cancelling rolls the run back through the same transaction a failure would use, so the report on disk is left untouched. Closing the window during a re-render also cancels it and waits for the rollback instead of killing the thread mid-swap.

## Fixed

- **Cancelling now stops the pages that are already running.** Before, "Отмена" only dropped the pages still in the queue: the cancel check lives in the progress callback, which fires when a page *finishes*, so every started page ran to completion first — on a large sheet at high DPI that is tens of seconds of waiting. The comparison now stops at the next phase boundary (before each render, before the diff, before writing output) and leaves no partial run folder behind. Cancellation is honored during alignment and report generation too, not only between pages.
- **A cancelled re-render no longer leaves `.rerender_*` staging debris** in the run folder.
- **The report bundle and `start.html` are published together** (carried over from v0.1.15): a failure in the final step can no longer leave a new report behind a stale entry point.

## Changed

- **Reproducible builds** — CI installs a single hashed lock file (`requirements/lock.txt`, `pip install --require-hashes`) in both the test and the build job, so the same commit always builds against the same dependency set, PyInstaller included. GitHub Actions are pinned by commit SHA. Running from source is unaffected (`base.txt` / `dev.txt` / `mcp.txt` keep loose ranges); `docs/RELEASE_PROCESS.md` explains how to regenerate the lock.

## Verification

- `142 passed`; `pdfcompare_core` coverage 86.71% (gate: 82%); ruff and strict mypy clean.
- Cancellation tests: cancel before start (sequential and pooled), abort at the first checkpoint, abort between render and diff, cancel flag delivery into a spawned pool worker, cancelled re-render leaves the report byte-identical, no partial run folder or staging debris left behind.
