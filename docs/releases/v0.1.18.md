# PDFCompare Local v0.1.18

Hotfix: тихое автообновление могло оставить приложение незапускаемым.

## Что было

После автообновления вылезала ошибка:

```
Failed to load Python DLL 'C:\Users\…\AppData\Local\Temp\_MEI282082\python312.dll'.
LoadLibrary: Не найден указанный модуль.
```

Инсталлятор ставил **one-file** сборку. Такой EXE при каждом старте распаковывает Python-рантайм в `%TEMP%\_MEI<PID>` и **удаляет эту папку при выходе**. При тихом обновлении инсталлятор закрывает работающее приложение и тут же запускает новое, а Windows переиспользует идентификаторы процессов мгновенно — и новый процесс мог начать распаковку ровно в ту папку, которую умирающий старый в этот момент удалял. Получался наполовину распакованный рантайм: `python312.dll` на месте, а его зависимости (CRT) — нет.

Сама установка при этом проходила успешно: ломался только автоматический перезапуск, и приложение запускалось из меню «Пуск».

## Что сделано

- **Инсталлятор ставит one-dir сборку**: рантайм лежит рядом с EXE, распаковки во временную папку нет вообще — гонке негде возникнуть. Побочно приложение стартует заметно быстрее.
- **Одиночный EXE остался** как отдельная загрузка для тех, кому нужен один файл: там ничего с ним не конкурирует.
- **UPX-сжатие выключено.** Сжатие `python3xx.dll` и CRT — второй документированный способ получить ровно эту же ошибку; сэкономленный размер того не стоит.
- CI проверяет, что в one-dir payload действительно лежит `python3xx.dll` рядом с EXE.

## Проверка

- One-dir сборка собрана и **запущена**: процесс живёт, рантайм грузится; `python312.dll`, `VCRUNTIME140_1.dll`, `tk86t.dll` на месте.
- Остальное без изменений: ruff и strict mypy чисты, 162 теста, coverage 88%.

## Если вы уже поймали эту ошибку

Установка прошла — просто запустите приложение из меню «Пуск». Дальше оно обновится на 0.1.18 само.
